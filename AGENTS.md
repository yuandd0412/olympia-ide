# Olympia IDE — Project Agent Guide

> Repo folder `oler-ide-v2` keeps the legacy v2 codename; the product name everywhere user-facing is **Olympia IDE**.

## Project at a Glance
Desktop OI (Olympiad in Informatics) coding IDE: dark-mode-first, information-dense, built-in compile/run pipeline, problem ingest, stress tester, and AI coach.

- `frontend/` — Tauri 2 + React 19 + TypeScript desktop app. **Retired as a shipping product** (v0.1.0); it stays for reference, and its feature list is the yardstick the fork is measured against (「老版本有的我们也要有」).
- `oss/` — the **Olympia IDE** VS Code fork (product `Olympia`, base 1.140.0). It is a second shipping product, not a vendored dependency: it carries three self-written built-in extensions (`olympia-onboarding`, `olympia-contest`, `olympia-coach`) and the whole Chinese-localized workbench.
- The early Qt 6.8/C++17 foundation implementation was removed from the mainline (tag `qt-foundation` preserves it; its build lessons live in `docs/07-risks/`).

## Conventions
- Project root stays ASCII (`D:\oler-ide-v2`) — never introduce CJK paths in build tooling.
- "Done" is defined by user confirmation on a real machine OR automated tests passing — never by the assistant's own confidence.

## Frontend (Tauri) Line
- Location: `frontend/`. Stack: Tauri 2.x · React 19 · TypeScript · Vite · Monaco Editor (`@monaco-editor/react`) · Zustand store · Tailwind CSS 4 · framer-motion. (xterm.js and the integrated terminal were removed in v0.1.0.)
- Dev loop: `cd frontend && npm install && npm run tauri dev` (launches Vite dev server + the Tauri window).
- Frontend-only checks: `npm run build` (tsc typecheck + vite build); `npm run lint` (oxlint).
- Rust backend checks: `cd frontend/src-tauri && cargo check --all-targets` and `cargo test --lib`.
- Rust backend crate: `frontend/src-tauri` (package `app`, lib target `app_lib`, smoke bin `test_ingest`). Modules: `ai.rs` / `enrich.rs` / `ingest.rs` / `models.rs` / `multi_oj.rs` / `pdf_extract.rs` / `practice.rs` / `runner.rs` / `storage.rs` / `stress.rs` / `toolchain.rs`.
- Judge memory: peak working set is sampled through `runner::ProcessHandle`, an `OpenProcess(PROCESS_QUERY_INFORMATION | PROCESS_VM_READ)` handle taken while the child is still alive. `tokio::process::Child` closes its own handle as soon as `wait()` reaps the process, so sampling afterwards returns nothing — a measured 0 KB means "not measured" (rendered `未测得` via `memoryLabel`) and must never escalate to MLE.
- External UI capabilities go through ports: `src/ports/{editor,layout,document,motion}` are the stable interfaces; `src/adapters/**` holds the third-party implementations (Monaco, react-resizable-panels, react-markdown+KaTeX, PDF extraction). Code under `components/**` must NOT import `@monaco-editor/react`, `monaco-editor`, `react-resizable-panels`, `react-markdown`, `remark-math`, `rehype-katex`, `katex` or `pdfjs-dist` directly, must not leak third-party types into props, and must reuse `ports/motion` tokens instead of ad-hoc easing curves. Grep acceptance: `grep -rn "@monaco-editor/react\|monaco-editor\|react-resizable-panels\|react-markdown\|remark-math\|rehype-katex\|katex\|pdfjs-dist" frontend/src/components` returns no import lines.
- Generated dirs are gitignored — never commit them: `frontend/node_modules`, `frontend/dist`, `frontend/src-tauri/target`, `frontend/src-tauri/vendor` (vendored toolchain).
- Fresh installs start with an EMPTY problem library (the old P1001 seed was removed); `problems.json` is created on first save.
- Pitfall: files parsed by Tauri's config/capability system (e.g. `src-tauri/capabilities/default.json`) must be plain UTF-8 WITHOUT BOM — a stray BOM broke capability parsing once (fix commit `ff23c92`). Same class of bug caused the UTF-8 mojibake sweep across components (commit `20a2267`); the throwaway repair scripts live archived under `scripts/oneoff/`.
- Encoding pitfall (root cause, 2026-09-10): the damaged text was **GBK bytes that got read as UTF-8**, which is lossy — every affected character froze into `U+FFFD` and cannot be recovered from git. To detect a recurrence, grep for `\x{FFFD}` — a plain-text console read will NOT show it (this shell is Windows PowerShell 5.1, whose `Get-Content` defaults to cp936 and renders any UTF-8 Chinese as mojibake). Rust sources in this repo are commented in English.
- Known lint debt (updated 2026-10-10): 4 residual oxlint warnings are INTENTIONAL — do not "fix" them mechanically.
  - `react(purity)` ×2 (`Date.now()` during render): `ActivityBar.tsx:17`, `AiCoachPage.tsx:59`. A pure fix needs a ticking contest-clock source or a store-level expiry sweep; replacing with `contestEndTime !== null` alone would leave the AI lock engaged forever after a restart past an expired persisted deadline.
  - `react(set-state-in-effect)` ×2: `ContestBar.tsx:17` (countdown and similar timer syncs — existing pattern works; converting to derived state changes render timing), `OnboardingWizard.tsx:50` (toolchain detection).
  - The two former `SettingsPage` warnings (purity + form sync) were eliminated by the settings-form refactor, not by mechanical fixes, and the wizard's `exhaustive-deps` warning on the Escape handler went away by memoising `handleSkip` rather than by ignoring the rule.

### Toolchain Strategy (Single Full Installer)
- **Single distribution** (`npm run tauri build`, ~49 MB): every installer embeds the stripped `src-tauri/vendor/mingw64/` as a bundle resource next to the exe (`bundle.resources` map form — the mixed string+object array form silently drops the map entry). The slim variant and `tauri.full.conf.json` / rename script were removed.
- **Vendor preparation**: after re-vendoring a fresh 7z, run `python scripts/strip-toolchain.py` FIRST — gdb/opt/Fortran/LTO out; `liblto_plugin.dll` must STAY (the linker requires it on every link). Unstripped, the installer exceeds Gitee's 100 MB attachment limit.
- `detect_toolchain` in `src-tauri/src/toolchain.rs` probes bundled resource → `~/.oleride/mingw64` → configured path → PATH, in that order; the onboarding wizard offers a one-click pinned MinGW 13.1.0 download (TUNA mirror, sha256-verified) when nothing is found.
- Publishing: `website/DEPLOY.md` + `node build/make-release.mjs`. **The version number lives in exactly one place: `olympiaVersion` in `oss/product.json`.** `make-release.mjs` derives `--tag` from it and refuses a `--tag` that disagrees; `check-website.mjs` derives the `dist/olympia-release-v<x>` directory and the release tag every download button must point at from it; and 关于 shows `1.0.0（VS Code 1.140.0）` because `productService.version` — injected from `oss/package.json` at bundle time, i.e. the upstream base — is a *different* number that students must never have to reconcile with the site. To ship a new version: edit `olympiaVersion`, nothing else. The release artifact is the **fork** installer (measured 2026-10-15: 294,804,121 B = 281 MiB across 5 files), which no host in use can carry as a single file (Cloudflare Pages caps files at 25 MiB, Gitee Release attachments at 100 MB decimal), so it ships as Inno's own disk-spanning slices: `OlympiaSetup.exe` + `OlympiaSetup-N.bin`, 90 MiB each, all dropped into one folder and run from the exe; `OlympiaSetup-web.exe` (1.8 MB, `oss/build/win32/code-web.iss`, tag compiled in) is what the website buttons link. The Tauri 0.1.0 build it replaced was 49 MB and fitted in one attachment — `website/` no longer links it (`check-website.mjs` fails the build if any page links `_0.1.0_x64-setup.exe`), but the **deployed** site still did on 2026-10-15, which is why DEPLOY.md now orders upload → `check-website.mjs --online` → deploy. Its "安装需要管理员权限" note is wrong for the fork user installer (`PrivilegesRequired=lowest`, installs to `%LOCALAPPDATA%\Programs\Olympia IDE`).
- Legal (fork reality, checked by `node scripts/oneoff/check-licence-surface.mjs`, and — against the finished product directory — `node build/verify-product-licence.mjs <productDir>`, which `build/oss-package.ps1` runs after the toolchain check): the package carries `NOTICE.olympia.txt` (Chinese component notice, UTF-8 **with BOM** in the repo — BOM-less UTF-8 renders as GBK mojibake on zh-CN Windows; note that gulp **strips the BOM** on the way into `resources/app/`, while the Inno licence page reads the repo copy, which keeps it), `GPL-3.0.txt` (the GNU text itself: the product declares GPL-3.0-or-later in four places, and GPL §4 wants a copy of the licence with every copy — a webpage saying "we are GPL" is not that), `LICENSE.txt` (Microsoft MIT; `product.json.licenseFileName` must name a file that exists) and `resources/app/ThirdPartyNotices.txt` (measured 2026-10-15: **83** npm/git entries — 166 separator lines, which is where an earlier "~166 组件" claim came from and why the gate now counts them); `LICENSES.chromium.html` stays at the product root. The Inno wizard's licence page is decided by one macro, `RootLicenseFileName` in `oss/build/win32/code.iss`, which now prefers `NOTICE.olympia.txt`. There is **no** `npm run notices` / `notices:check` and nothing ships named `THIRD-PARTY-NOTICES.md` — that file and those scripts belong to the retired Tauri frontend (`frontend/src-tauri/`), and its GCC 13.1.0 / `mingw64/licenses/` claims are stale for the fork, which bundles MSYS2 GCC 15.2.0 with texts under `toolchain/mingw64/share/licenses/`.

- Security surface (measured 2026-10-11, not assumed) — **this all lives in the retired Tauri frontend, which no longer ships**; it is recorded so nobody re-audits it as a live exposure. The asset protocol is scoped to `["**/*.pdf", "**/*.PDF"]` because the entire frontend has exactly one `convertFileSrc` call (`services/tauriApi.ts:299 pdfAssetUrl`), consumed only by the PDF viewer iframe, and PDF paths can only come from `pickPdfFile` (`tauriApi.ts:289`, `extensions: ['pdf']`). It used to be `["**"]`, i.e. any readable file on disk was reachable from the webview — **do not widen it back** without re-running that check. Two exposures remain and were never decided: `"csp": null`, and `capabilities/default.json` granting `fs:allow-read-text-file` / `fs:allow-write-text-file` at `path: "**"`. The fs pair cannot simply be narrowed because `tauriApi.readFile/writeFile` back source loading and saving (`useAppStore.ts:456/580/814/831`) and the save target is whatever the user picks in the save dialog, which a static scope cannot express; the sound fix is moving that IO into Rust commands and then revoking the fs permissions. If `frontend/` is ever rebuilt for distribution these two become live again — the fork's equivalent surface is `oss/` (extension host + `fs` provider), not this config.
- Capability/config JSON must stay plain UTF-8 without BOM — see the pitfall above.

## VS Code Fork (`oss/`) Line
- Build: `build/oss-package.ps1` runs the four stages (bundle → toolchain → package → node-compile-cache) that produce the unpacked product in `VSCode-win32-x64/` and the installer. `build/oss-compile.ps1` / `build/oss-ci.ps1` are the shorter compile and verify paths.
- **`oss/` is an embedded git repository.** The outer repo cannot track anything inside it and `.gitignore` negations do not help; fork-side history is committed inside `oss/` itself. No identity is configured there, so pass it inline (`git -C oss -c user.name=… -c user.email=… commit …`) and never write to any git config.
- Localisation rewrites files in place; no language pack is registered, so the workbench locale stays `en`. `build/apply-zh-cn-ast.mjs` translates NLS literals in `oss/src` from the dictionaries `build/zh-cn-dict-*.mjs`; `build/gen-ext-nls-from-langpack.mjs` rewrites each bundled extension's `package.nls*.json` from the official zh-hans donor pack; `build/audit-*.mjs` verify the result (brand leftovers, placeholder damage, key collisions). Re-run the generators after an upstream merge — `node build/audit-brand-leftovers.mjs` must report zero hits in the shipped tree.
- A new built-in extension must be added to the **hardcoded** `compilations` array in `oss/build/gulpfile.extensions.ts`: upstream's glob discovery there is commented out, so an unlisted extension compiles correctly and still ships absent.
- Upstream `hygiene` (the husky pre-commit hook inside `oss/`) enforces the Microsoft 4-line copyright header, a non-ASCII guard, an indentation guard and TS-language-service formatting. Fork-authored exceptions belong in `oss/build/filters.ts` (already exempts `extensions/olympia-*/**` for unicode and the contest template file for indentation) — extend that list instead of silencing guards line by line.
- Gate rule for core l10n (superseded 2026-10-11 — read this instead of the old marker recipe): the unicode guard no longer looks at `src/vs` at all, because `oss/build/filters.ts` lists `'!src/vs/**'` in `unicodeFilter`. Reason, recorded with the exemption: in-place localisation puts 22,955 Chinese message literals in 1,893 upstream files, and policing that per line means inserting ~21,800 `// allow-any-unicode-next-line` comments into vendored source, i.e. a merge conflict on every future upstream pull. This is the same argument the fork already accepted for `'!extensions/olympia-*/**'`. **Only unicode is relaxed** — copyright, indentation and TS formatting still run over `src/vs`, and brand leftovers stay covered by `build/audit-brand-leftovers.mjs`. Consequence: a core l10n batch is now `node build/apply-zh-cn-ast.mjs --dict=…` → commit, with no marker pass. `scripts/oneoff/add-unicode-markers.py` still matters for non-`src/vs` paths that the guard does police (it now also accepts `--from-log=<hygiene log>` and `--dry`). Batches 70/71 keep their markers: redundant under the exemption, but harmless and not worth a second mass edit.
- `npm run hygiene` from `oss/` is a real whole-tree gate again: it exits 0 over 12,449 files as of `oss` commit `73541432`. It previously could not even complete on Windows — `path.dirname(new URL(import.meta.url).pathname)` returns the POSIX-shaped `/D:/…`, so `path.join` produced `D:\D:\oler-ide-v2\oss\remote\package.json` and the task died with ENOENT before checking anything (fixed with `fileURLToPath`). Two long-standing false positives went with it: `*.tgz` is excluded from the copyright guard (gzip bytes are not source), and `src/vs/platform/agentHost/node/agentHostServerMain.ts` is excluded from the TS-formatting guard because it is upstream-authored and untouched since the baseline `44475326`, so reformatting it would be pure merge drift. Beware when reading any of these results: `cmd | tail` reports **tail's** exit code, which has fooled this project twice — capture `$?` from the command itself.
- The residual translation gap is measurable rather than folklore, but the counter has to share the applier's node rules: `node scripts/oneoff/nls-residual-ast.mjs` (runs from any cwd; resolves `oss/src/vs` from its own location). Measured 2026-10-11 (after batches 71–80): 27,873 reachable `localize*` messages, 23,133 already zh-cn (83.0%), **4,448 still English — but only 2,040 of those are in surfaces this product runs**, because most belong to Copilot-only machinery the fork does not run (Sessions/Agents window, `platform/agentHost`, MCP/voice/browser-view, customization marketplace; the list lives in `PRODUCT_UNREACHABLE`). Almost all of the 2,054 is `workbench/contrib/chat` — i.e. the chat widget `@coach` renders into is the remaining job, and everything else is in tens. Batches 71–80 landed 177 literals in 10 commits and every one was hit-rate-verified (33/33, 10/10, 16/16, 29/29, 17/17, 15/15, 5/5, 24/24, 6/6, 7/7), then re-checked with `build/audit-key-collisions.mjs` — whose `APPLIED-MULTI` also counts sites earlier batches already translated, so read it against the applier's own `APPLIED: n literals / m files` before concluding a key fanned out. Two rules batches 77–78 established: translate a whole conditional set at once (the two branches of one ternary, or two strings in one function, must not end up one Chinese and one English on screen), and leave the *name* of a command/button untranslated inside a translated sentence when the fork has no localize site for that label — e.g. 「请使用 Open Full Output (Read-Only) 查看已捕获的输出。」 — otherwise the copy points at a button the user cannot find. The older regex counters (`nls-gap-scan.py`, `nls-gap-split.py`, `nls-dump-english.py`) disagree with the AST pass **in both directions**: they also match `localize` calls sitting inside comments, which no dictionary can ever fix (taskTemplates.ts's `/* Version 1.0 templates */` block, the commented `MenuRegistry.addCommand` pair in task.contribution.ts), while missing object-literal keys, >200-char messages and template literals — they reported 4,457 against a reachable 4,626. Two consequences of that trap are recorded in `build/zh-cn-dict-70.mjs`: keys aimed at commented-out code never match, and a key whose English default was already rewritten in place also reports as unmatched, so a `--dry` run against an applied batch legitimately shows `0 / N`. All three regex tools now resolve their own scan root and refuse to print a number when they read no files; before that they each answered **`0 / 0`** when run from the repo root, because `os.walk('src/vs')` over a missing directory yields nothing — which is how "nothing left to translate" got fabricated twice. Prioritise by area and by whether the surface is reachable in this product, never by the total count.
- Pitfall: never point `product.json`'s `defaultChatAgent.chatExtensionId` or `.extensionId` at `olympia.coach`. `ensureChatExtensionInitialDisabledState` (`oss/src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts:155-190`) silently and *persistently* disables any built-in whose id equals `chatExtensionId` until chat setup is completed, and `_isDisabledByUnification` (`:663`, reached from `:504`) disables `extensionId` while `chat.extensionUnification.enabled` is on. `olympia-coach` therefore ships as an ordinary built-in that registers a chat participant, and the leftover `olympia.olympia-coach` ids are deliberate.
- `defaultChatAgent.byokOnly: true` (oss commit `ca1cd4f9`) is what removes the Copilot sign-in / plan / account chrome. The phantom `chatExtensionId` above keeps `ChatContextKeys.Setup.installed` false **upstream**, but the byokOnly branch overwrites it: it sets `Setup.hidden/installed/completed` true and **returns before `ChatEntitlementContext` and `ChatEntitlementRequests` are created**, which is also what stops every window start from calling a vendor entitlement/quota endpoint. `DefaultAccountProviderContribution` skips registering its account provider under the same flag. If you ever remove `byokOnly` from `product.json`, all of that chrome comes back.
- Two consequences of that "installed = true" were found on 2026-10-15 by reading the **shipped** product, not the source (both now covered by `node scripts/oneoff/check-chat-product-ids.mjs`): (1) the constructor only writes context keys, so `ChatEntitlementService.sentiment.hidden` stayed **false** in the instance `ChatService.activateDefaultAgent` reads, and every session still logged `No default agent contributed` — fixed by a `hiddenByProduct` field OR-ed into the getter, because the product flag is the answer and context-key propagation is not. (2) with `installed` true, the chat title-bar 「配置内联建议…」 item shows up and executes `defaultChatAgent.completionsMenuCommand`, which resolves to nothing in this product; its precondition now also requires `chatSetupHidden == false`. Dead-but-inert ids (`walkthroughCommand`, `chatRefreshTokenCommand`, `completionsEnablementSetting`, `nextEditSuggestionsSetting`, `completionsAdvancedSetting`) are kept as upstream leaves them and **registered in that gate with the reason each is unreachable** — the gate re-reads the guarding source line, so deleting the guard turns it red rather than letting "temporarily unreachable" rot into "nobody remembers".
- **Dev loop: `out/` has two mutually exclusive shapes, and only one of them boots.** `node build/next/index.ts bundle --out out` (≈10 s, reads `src/` directly) emits the 25 bundles **plus** `out/vs/workbench/workbench.desktop.main.css`; that is the only build that a dev window can start from, because the per-module builds (`npm run compile-client`, `npm run transpile-client`) leave raw `import './media/x.css'` statements in the emitted JS, Chromium rejects a `text/css` response as an ES module, and the window comes up empty with `Failed to fetch dynamically imported module: …/workbench.desktop.main.js` and no `window1/renderer.log` at all. The per-module tree is what the source gates read (`check-core-copy.mjs` etc.), so after a device check run `npm run transpile-client` (≈76 s) before the gates. Both commands `rm -rf` their output dir, so whichever runs last owns `out/`; a gate whose file has vanished reports FAIL rather than passing.
- **The chat panel needs a *default agent*, not just a chat participant.** `getDefaultAgent` (`oss/src/vs/workbench/contrib/chat/common/chatAgents.ts:459`) requires `isDefault && locations ∋ panel && modes ∋ ask`, and `chatParticipant.contribution.ts:268-276` skips the whole manifest entry unless `enabledApiProposals` carries `defaultChatParticipant` (plus `chatParticipantAdditions` for `locations`) — so `olympia-coach` can be registered, visible in the model picker, and still make every send a no-op (`sendRequest No default agent for location panel` in `renderer.log`, draft never clears, no HTTP request). `node scripts/oneoff/check-chat-product-ids.mjs` pins those five facts. See `docs/11-fork/extensions.md`.

## File Deletion Rules
- The assistant MUST NEVER run `Remove-Item` / `rm` / `del` / `Move-Item to /dev/null` directly.
- For recursive deletes, suggest `cmd /c rmdir /s /q <ASCII-absolute-path>` and let the user run it — PowerShell `Remove-Item` is blocked by the desktop permission gate (Wipe category).
- `cmd /c rmdir /s /q` uses the .NET API and is NOT blocked by the gate.

## Per-Step Self-Check
- Report at the end of every research/design/implementation step, then wait for approval before continuing.
- Irreversible actions (kill process / delete file / rewrite git history) require explicit user confirmation every time.
