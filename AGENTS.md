# Olympia IDE — Project Agent Guide

> Repo folder `oler-ide-v2` keeps the legacy v2 codename; the product name everywhere user-facing is **Olympia IDE**.

## Project at a Glance
Desktop OI (Olympiad in Informatics) coding IDE: dark-mode-first, information-dense, built-in compile/run pipeline, problem ingest, stress tester, and AI coach.

- `frontend/` — Tauri 2 + React 19 + TypeScript desktop app. **Retired as a shipping product** (v0.1.0); it stays for reference, and its feature list is the yardstick the fork is measured against (「老版本有的我们也要有」).
- `oss/` — the **Olympia IDE** VS Code fork (product `Olympia`, base 1.140.0). It is a second shipping product, not a vendored dependency: it carries three self-written built-in extensions (`olympia-onboarding`, `olympia-contest`, `olympia-coach`) and the whole Chinese-localized workbench.
- The early Qt 6.8/C++17 foundation implementation was removed from the mainline (tag `qt-foundation` preserves it; its build lessons live in `docs/07-risks/`).

## Conventions
- Project root stays ASCII (`D:\oler-ide-v2`) — never introduce CJK paths in build tooling.
- "Done" is defined by user confirmation on a real machine OR automated tests passing — never by the assistant's own confidence.

## Frontend (Tauri) Line
- Location: `frontend/`. Stack: Tauri 2.x · React 19 · TypeScript · Vite · Monaco Editor (`@monaco-editor/react`) · Zustand store · Tailwind CSS 4 · framer-motion. (xterm.js and the integrated terminal were removed in v0.1.0.)
- Dev loop: `cd frontend && npm install && npm run tauri dev` (launches Vite dev server + the Tauri window).
- Frontend-only checks: `npm run build` (tsc typecheck + vite build); `npm run lint` (oxlint).
- Rust backend checks: `cd frontend/src-tauri && cargo check --all-targets` and `cargo test --lib`.
- Rust backend crate: `frontend/src-tauri` (package `app`, lib target `app_lib`, smoke bin `test_ingest`). Modules: `ai.rs` / `enrich.rs` / `ingest.rs` / `models.rs` / `multi_oj.rs` / `pdf_extract.rs` / `practice.rs` / `runner.rs` / `storage.rs` / `stress.rs` / `toolchain.rs`.
- Judge memory: peak working set is sampled through `runner::ProcessHandle`, an `OpenProcess(PROCESS_QUERY_INFORMATION | PROCESS_VM_READ)` handle taken while the child is still alive. `tokio::process::Child` closes its own handle as soon as `wait()` reaps the process, so sampling afterwards returns nothing — a measured 0 KB means "not measured" (rendered `未测得` via `memoryLabel`) and must never escalate to MLE.
- External UI capabilities go through ports: `src/ports/{editor,layout,document,motion}` are the stable interfaces; `src/adapters/**` holds the third-party implementations (Monaco, react-resizable-panels, react-markdown+KaTeX, PDF extraction). Code under `components/**` must NOT import `@monaco-editor/react`, `monaco-editor`, `react-resizable-panels`, `react-markdown`, `remark-math`, `rehype-katex`, `katex` or `pdfjs-dist` directly, must not leak third-party types into props, and must reuse `ports/motion` tokens instead of ad-hoc easing curves. Grep acceptance: `grep -rn "@monaco-editor/react\|monaco-editor\|react-resizable-panels\|react-markdown\|remark-math\|rehype-katex\|katex\|pdfjs-dist" frontend/src/components` returns no import lines.
- Generated dirs are gitignored — never commit them: `frontend/node_modules`, `frontend/dist`, `frontend/src-tauri/target`, `frontend/src-tauri/vendor` (vendored toolchain).
- Fresh installs start with an EMPTY problem library (the old P1001 seed was removed); `problems.json` is created on first save.
- Pitfall: files parsed by Tauri's config/capability system (e.g. `src-tauri/capabilities/default.json`) must be plain UTF-8 WITHOUT BOM — a stray BOM broke capability parsing once (fix commit `ff23c92`). Same class of bug caused the UTF-8 mojibake sweep across components (commit `20a2267`); the throwaway repair scripts live archived under `scripts/oneoff/`.
- Encoding pitfall (root cause, 2026-09-10): the damaged text was **GBK bytes that got read as UTF-8**, which is lossy — every affected character froze into `U+FFFD` and cannot be recovered from git. To detect a recurrence, grep for `\x{FFFD}` — a plain-text console read will NOT show it (this shell is Windows PowerShell 5.1, whose `Get-Content` defaults to cp936 and renders any UTF-8 Chinese as mojibake). Rust sources in this repo are commented in English.
- Known lint debt (updated 2026-10-10): 4 residual oxlint warnings are INTENTIONAL — do not "fix" them mechanically.
  - `react(purity)` ×2 (`Date.now()` during render): `ActivityBar.tsx:17`, `AiCoachPage.tsx:59`. A pure fix needs a ticking contest-clock source or a store-level expiry sweep; replacing with `contestEndTime !== null` alone would leave the AI lock engaged forever after a restart past an expired persisted deadline.
  - `react(set-state-in-effect)` ×2: `ContestBar.tsx:17` (countdown and similar timer syncs — existing pattern works; converting to derived state changes render timing), `OnboardingWizard.tsx:50` (toolchain detection).
  - The two former `SettingsPage` warnings (purity + form sync) were eliminated by the settings-form refactor, not by mechanical fixes, and the wizard's `exhaustive-deps` warning on the Escape handler went away by memoising `handleSkip` rather than by ignoring the rule.

### Toolchain Strategy (Single Full Installer)
- **Single distribution** (`npm run tauri build`, ~49 MB): every installer embeds the stripped `src-tauri/vendor/mingw64/` as a bundle resource next to the exe (`bundle.resources` map form — the mixed string+object array form silently drops the map entry). The slim variant and `tauri.full.conf.json` / rename script were removed.
- **Vendor preparation**: after re-vendoring a fresh 7z, run `python scripts/strip-toolchain.py` FIRST — gdb/opt/Fortran/LTO out; `liblto_plugin.dll` must STAY (the linker requires it on every link). Unstripped, the installer exceeds Gitee's 100 MB attachment limit.
- `detect_toolchain` in `src-tauri/src/toolchain.rs` probes bundled resource → `~/.oleride/mingw64` → configured path → PATH, in that order; the onboarding wizard offers a one-click pinned MinGW 13.1.0 download (TUNA mirror, sha256-verified) when nothing is found.
- Publishing: `website/DEPLOY.md` + `node build/make-release.mjs`. **The version number lives in exactly one place: `olympiaVersion` in `oss/product.json`.** `make-release.mjs` derives `--tag` from it and refuses a `--tag` that disagrees; `check-website.mjs` derives the `dist/olympia-release-v<x>` directory and the release tag every download button must point at from it; and 关于 shows `1.0.0（VS Code 1.140.0）` because `productService.version` — injected from `oss/package.json` at bundle time, i.e. the upstream base — is a *different* number that students must never have to reconcile with the site. To ship a new version: edit `olympiaVersion`, nothing else. **出包是两步，少跑第一步不会报错**：`build/oss-package.ps1` 拼产品目录 `VSCode-win32-x64/`，`gulp vscode-win32-x64-user-setup` 只是把那个目录压进安装器；只跑后一步 = 把上一次构建留在目录里的字节再压发一遍（2026-10-18 实测：扩展改了、ISCC 跑了 18 分钟、产物里还是旧的）。`make-release.mjs` 现在会先比每个 `olympia-*` 扩展 `src/` 的 TS 与产品目录 `out/` 的 JS 谁更新，旧了拒绝出发布目录；**并且**跑一遍 `build/verify-product-workbench.mjs` 来卡 workbench 主包的新鲜度 —— 判据是**内容**不是 mtime（改一个字符重打包必然换 mtime，但「mtime 变过」不等于「里面是这次的字节」：打包中途失败会留下旧文件而打包脚本一路 EXITCODE=0）。补这一段是因为 2026-10-25 两边独立确认了一个真实缺口：扩展的 `out/` 被卡住了，**workbench 主包没有**，「扩展是新的、主包是旧的」这种混搭能一路走到 Gitee 附件上，用户装到的是上一次的首页 / 设置页；现已按「收包前跑产物门禁」补上，并用「从 NLS 消息表里摘掉一条源码声明过的 localize2 文案 → make-release 必须 exit 1 并点名 → 还原后 SHA-256 逐字节一致 → 变绿」证明它会咬。 The release artifact is the **fork** installer (measured 2026-10-15: 294,804,121 B = 281 MiB across 5 files), which no host in use can carry as a single file (Cloudflare Pages caps files at 25 MiB, Gitee Release attachments at 100 MB decimal), so it ships as Inno's own disk-spanning slices: `OlympiaSetup.exe` + `OlympiaSetup-N.bin`, 90 MiB each, all dropped into one folder and run from the exe; `OlympiaSetup-web.exe` (1.8 MB, `oss/build/win32/code-web.iss`, tag compiled in) is what the website buttons link. The Tauri 0.1.0 build it replaced was 49 MB and fitted in one attachment — `website/` no longer links it (`check-website.mjs` fails the build if any page links `_0.1.0_x64-setup.exe`), but the **deployed** site still did on 2026-10-15, which is why DEPLOY.md now orders upload → `check-website.mjs --online` → deploy. Its "安装需要管理员权限" note is wrong for the fork user installer (`PrivilegesRequired=lowest`, installs to `%LOCALAPPDATA%\Programs\Olympia IDE`).
- Legal (fork reality, checked by `node scripts/oneoff/check-licence-surface.mjs`, and — against the finished product directory — `node build/verify-product-licence.mjs <productDir>`, which `build/oss-package.ps1` runs after the toolchain check): the package carries `NOTICE.olympia.txt` (Chinese component notice, UTF-8 **with BOM** in the repo — BOM-less UTF-8 renders as GBK mojibake on zh-CN Windows; note that gulp **strips the BOM** on the way into `resources/app/`, while the Inno licence page reads the repo copy, which keeps it), `GPL-3.0.txt` (the GNU text itself: the product declares GPL-3.0-or-later in four places, and GPL §4 wants a copy of the licence with every copy — a webpage saying "we are GPL" is not that), `LICENSE.txt` (Microsoft MIT; `product.json.licenseFileName` must name a file that exists) and `resources/app/ThirdPartyNotices.txt` (measured 2026-10-15: **83** npm/git entries — 166 separator lines, which is where an earlier "~166 组件" claim came from and why the gate now counts them); `LICENSES.chromium.html` stays at the product root. The Inno wizard's licence page is decided by one macro, `RootLicenseFileName` in `oss/build/win32/code.iss`, which now prefers `NOTICE.olympia.txt`. There is **no** `npm run notices` / `notices:check` and nothing ships named `THIRD-PARTY-NOTICES.md` — that file and those scripts belong to the retired Tauri frontend (`frontend/src-tauri/`), and its GCC 13.1.0 / `mingw64/licenses/` claims are stale for the fork, which bundles MSYS2 GCC 15.2.0 with texts under `toolchain/mingw64/share/licenses/`.

- Security surface (measured 2026-10-11, not assumed) — **this all lives in the retired Tauri frontend, which no longer ships**; it is recorded so nobody re-audits it as a live exposure. The asset protocol is scoped to `["**/*.pdf", "**/*.PDF"]` because the entire frontend has exactly one `convertFileSrc` call (`services/tauriApi.ts:299 pdfAssetUrl`), consumed only by the PDF viewer iframe, and PDF paths can only come from `pickPdfFile` (`tauriApi.ts:289`, `extensions: ['pdf']`). It used to be `["**"]`, i.e. any readable file on disk was reachable from the webview — **do not widen it back** without re-running that check. Two exposures remain and were never decided: `"csp": null`, and `capabilities/default.json` granting `fs:allow-read-text-file` / `fs:allow-write-text-file` at `path: "**"`. The fs pair cannot simply be narrowed because `tauriApi.readFile/writeFile` back source loading and saving (`useAppStore.ts:456/580/814/831`) and the save target is whatever the user picks in the save dialog, which a static scope cannot express; the sound fix is moving that IO into Rust commands and then revoking the fs permissions. If `frontend/` is ever rebuilt for distribution these two become live again — the fork's equivalent surface is `oss/` (extension host + `fs` provider), not this config.
- Capability/config JSON must stay plain UTF-8 without BOM — see the pitfall above.

## VS Code Fork (`oss/`) Line
- Build: `build/oss-package.ps1` runs the four stages (bundle → toolchain → package → node-compile-cache) that produce the unpacked product in `VSCode-win32-x64/` and the installer. `build/oss-compile.ps1` / `build/oss-ci.ps1` are the shorter compile and verify paths.
- **Compile-green is not artifact-fresh (measured 2026-10-25).** `build/oss-compile.ps1` runs typecheck + `build/next/index.ts transpile` only, which writes `oss/out` as a ~10 KB loader plus separate per-module files — it does **not** produce the shipped bundle. The shipped `resources/app/out/vs/workbench/workbench.desktop.main.js` is produced by `build/oss-package.ps1` STAGE 1 (`build/next/index.ts bundle --nls`) and STAGE 3 (`gulp vscode-win32-x64-ci`). So after touching product source under `oss/src/vs/workbench/contrib/olympia/`, a green `oss-compile.ps1` leaves the product directory byte-identical to the previous build. In the 2026-10-25 round the first bundle inspection read the *previous* round's bytes (25 markers found, 6 missing — missing `.olympiaSettings-input`, `.olympiaSettings-checkbox`, `grid-template-rows: auto minmax(0, 1fr) auto`, `grid-row: 1 / span 3`) until `oss-package.ps1` was re-run in full (never with `-SkipBundle`); afterwards all 31 markers matched. This is one layer below the "出包是两步" installer note below: that one covers `oss-package.ps1` → `gulp vscode-win32-x64-user-setup`, this one covers `oss-compile.ps1` → `oss-package.ps1`. **Rule: after editing product source, the only legitimate way to refresh the artifact is a full `build/oss-package.ps1`; a compile-only run is not a substitute and reports no error.**
- **The product gate reads the bundle, and it strips comments before deriving markers.** `build/verify-product-workbench.mjs` inspects the two shipped bundle files (`workbench.desktop.main.js` / `.css`). Markers are derived from source, and the derivation has two traps found on 2026-10-25: (1) markers that exist **only inside comments** (`olympia.startPage.showIntroAnimation` in a block comment, `olympia-contest` in a line comment) must not count as "source has it", or the gate demands a product that legitimately lacks them — so the derivation strips comments first, tracking string state so `'http://x'` is not mangled; (2) `localize` / `localize2` **keys** are replaced by NLS indices at bundle time, so a key is not a product marker — only the default text is, and `localize2` defaults must be included or the gate misses a whole class of Chinese copy. **This second requirement was itself only half implemented until 2026-10-25**: the derivation regex was `localize\(` only, so every `localize2(...)` default (command titles/descriptions — e.g. `olympiaHome.contribution.ts` "打开 Olympia 首页" / "打开面向 OI 选手的 Olympia 首页。") was collected as **nothing**, and the keys were simultaneously excluded from the literal set — that whole class of copy had **zero** gate coverage while the doc above claimed it was included. Both directions were proved by mutation: under the old regex, changing a `localize2` default to text absent from the product NLS left the gate **green** (blind spot); under the fixed `localize2?\(...\)` the same mutation exits 1 and names the missing copy, and restoring the file byte-for-byte (SHA-256 identical) returns it to green. The gate's scope must also cover every surface we ship: it originally matched only `olympia-onboarding-*`, leaving the settings page and the home page outside it entirely, so a stale-product regression would have stayed green all the way through packaging. It now matches every `.olympia*` class and every `olympia.` / `olympia-` literal, and reports 17 classes / 92 literals / 120 NLS strings.
- **Gate expectations must be read from source, never pinned; and a sandbox must mirror the tree, not a hand-written file list (three gate failures found 2026-10-25 — in all three the gate was wrong, the product was right).** (1) `scripts/oneoff/mutation-test-olympia-start-page.mjs` built its sandbox by copying a hand-written `NEEDED` file list; when a constant moved into a new module (`olympiaHomeEmptyState.ts`, referenced from `olympiaWelcome.contribution.ts` through a computed property name) the list kept only the *use* site, so the sandbox's constant table was incomplete and assertion F4 was red **before any mutation ran** — the whole 148-mutation proof never executed and `check-all` was permanently red. Fix: `buildTree` now mirrors the entire `oss/src/vs/workbench/contrib/olympia/browser` directory, which removes the class of bug rather than this one instance. (2) `scripts/oneoff/verify-onboarding-no-break.mjs` asserted that the onboarding card still shows a full compiler command line (`-x c++` / `-std=c++23` / `-DONLINE_JUDGE`) and clicked "下一步" three times as if there were four cards — but commit `09e4b1f9` deliberately cut the flow from four cards to three and replaced the hand-written command with a summary read from the judge table (`GCC {0} · {1}`, source comment: "not hand-written numbers — numbers absent from the table must not appear on the card"). Six assertions were therefore false red while the product worked exactly as designed (the third click actually pressed the last card's "开始做题" and the enter animation did start). Fix: the gate now reads the card count and the expected summary **from the product source** (`OLYMPIA_ONBOARDING_CARD_COUNT`, the `localize2` template plus the judge table's luogu entry) and navigates by CTA text read **before** the click (reading it afterwards hits the `|| cards[0]` fallback once the overlay is gone). A future design change now moves the gate instead of breaking it. (3) `scripts/oneoff/check-backdrop-continuity.mjs` judged "the background keeps flowing" with the **mean** flow over the window, which dilutes "flows at first, then freezes": the freeze injection scored 0.05/100ms against a 0.04 floor and passed by luck, and the injection point (`triggerAt+6`) could even land outside the evaluated window entirely, making the injection unconditionally green. Fix: added C2c (longest continuous stall; >400 ms = red) and moved the injection to the first frame inside the window; the self-test gained S9 ("freeze in the middle of the animation"), because the old S3 froze from frame 0 and therefore proved something else. All three fixes were proved with a two-way teeth run (the new criterion goes red and names the cause; the old criterion stays green on the same mutation; real data stays green), and none of them touches product source, so no re-build and no re-release is required.
- **A gate only counts if it can bite — prove it by breaking it and restoring byte-for-byte.** Gates in this repo are judged by mutation, not by review: change the target into something wrong, the gate must go red **and name what is missing**, then restore the file and prove the restore was byte-identical by SHA-256 (not by "the diff looks empty"). For the product gate that run was `.olympiaSettings-input` → `.olympiaSettings-INPUT`: it exited 1 with `产物 CSS 里没有类名 .olympiaSettings-INPUT`, and the restored file hashed back to `064b43b0bb9b8ce2965e30b0f2c376fcd7ea8b40be41d6e0682d3296d299cf9c` before the gate returned to green. Same discipline as the mutation suites under `scripts/oneoff/` — a gate that cannot fail is documentation, not a gate.
- **外部审计报告的「缺陷」立项之前，先在被测源码里 grep 它的被测对象还在不在（2026-10-25：三条 ★/★★ 空窗里有三条是假的）。** T-039 的引导 CSS 覆盖矩阵（`.scratch/dispatch/t039-coverage-matrix.md`）逐条列了 52 项声明，行号指向 L207~L768 的**三屏改造前**的 CSS：它标 ★★ 的 #29/#30（预览块 `flex:1 1 auto` / `min-height:0`）、★ 的 #40/#44/#48（管道图 `align-content:center` / 流程图 `justify-content:center` / 目录树），以及 #27/#28/#42/#46/#50~#52，全部指向 `.olympia-onboarding-card-preview` / `-pipe` / `-flow` / `-directory` / `-code` / `-row` / `-options` —— 这些选择器在 2026-10-23 的三屏改造里**整族退役**（现行 `olympiaOnboarding.css` 里一个都 grep 不到；`verify-onboarding-geometry.mjs` 的 L-preview / L-code 判据也已退役，现役只有 L-center / L-bounds / L-gap / L-cta / L-choices / L-card-fit）。同理 T-036 的 Q2「420 档给行区加 `overflow:hidden` 静默裁剪」与 Q8「L-preview 只量底部空白不量溢出」也都指向已退役的行区与判据 —— **Q2 若照单执行，会白白触发「改 CSS → 重编译 → 重出安装器 → 重发 Gitee 附件 → 重部署官网数字」，而产品一行都不用改**（行区早没了；卡片自带的 `overflow:hidden` 的静默裁切由真机几何门 L-card-fit 覆盖：主按钮下沿越过 padding box 下沿、卡片 `scrollHeight − clientHeight` 超容差，两条都判红）。**规矩：任何复审/审计报告给出的「缺陷」立项之前，先在产品源码里 grep 它的被测选择器或判据 id，确认它还在；报告里的行号只能当线索，不能当证据**（行号是旧版的）。另一半同样重要：**同一件事可能已经被另一条断言钉住了** —— 矩阵 #12 与 Qoder Q1(b) 都说「默认档 `flex:0 0 auto` 无人钉」，但 T60 早就用 `cssRule(css, '.olympia-onboarding-choices')` 钉了 shrink=0，而 `cssRule` 取的是**全文件第一处**匹配 = 默认档（base）规则。新增断言前先搜「这个选择器 + 这个属性在别处钉过没有」，否则会写出一条与 T60 重复的断言。（附带：变异表里 `expect` 必须写断言的**确切 id** —— `T72` 不是 `T-72`；写错时变异其实红了，运行器却判它 FAIL，报错文案会误导成「断言没红」。）
- **字节复核类门禁必须先归一化行尾，而且 VERDICT 必须由复核结果算出来（2026-10-25：Gitee 同步脚本同时犯了假红和假绿）。** `scripts/oneoff/gitee-mirror-sync.mjs` 同步成功后复核关键文件时，拿**工作区原始字节**去比 Gitee 的 raw 字节 —— 但本仓 `core.autocrlf=true`，工作区签出是 CRLF、仓库里（以及镜像里）存的是 LF，于是**凡是签出过的文件必然对不上**（实测 `check-olympia-start-page.mjs` 被判 DIFF，而 Gitee 上的字节其实与 git blob 一模一样，`d2db7334…` = 工作区归一化后的值 = blob 值）。另一半更糟：`VERDICT=OK` 原本是**无条件打印**的，`BAD_COUNT=1` 时日志照样写着 OK —— 这正是「门禁必须有牙」的反例：一个只报错不咬人、还自带假绿的复核，比没有复核更坏。修法：比对改成三态（`MATCH` / `MATCH-EOL` 仅行尾不同、内容一致 / `DIFF` 真差异），**本地或远端读不到一律算 DIFF**（复核不了不等于通过），`VERDICT` 只在 `bad===0` 时才允许是 OK，并新增 `--verify-only`（不碰浏览器、只复核 head 与字节，可当独立发布门禁用）。牙齿证明 20/20：真内容差异 -> 红且 `VERDICT=FAIL`、纯行尾差异 -> 绿、本地读不到 -> 红、远端读不到 -> 红。**真正要记住的是这句：「一次假红 + 一次假绿」说明那个门禁当时根本没在工作** —— 上一轮报的「6/6 文件逐字节一致」其实是运气（那批文件工作区恰好是 LF），换个 CRLF 文件就翻车；门禁的输出必须能被独立复算，不能只看它有没有报错。
