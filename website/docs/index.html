使用手册 · 对应 v1.140.0 / Olympia v1.0.0

每一件事在哪里点

Olympia 是面向信息学竞赛的 VS Code fork。这份手册只讲 Olympia 自己加的那部分： 编译器与评测机档位、提交前体检、跑样例、对拍、比赛模式、题面与模板、AI 教练， 以及装完之后最容易卡住的地方。编辑器本身的操作和 VS Code 一样。

不想读全文？直接看十分钟上手或快捷键表。

十分钟上手

装完到第一次运行，正常只需要这三步。

  1. 打开题目文件夹。「文件 → 打开文件夹」选你放 .cpp 的目录。内置 g++ 15.2.0 会被自动找到，不需要配 PATH。
  2. 写代码，按 F9。Olympia 按当前评测机档位编译；编译通过后直接在面板里运行，输入可以现场敲，也可以选一个数据文件。
  3. 保存即体检。每次保存都会静默扫描会在评测机上编译失败的写法，结果显示在「问题」面板，不弹窗、不打断你打字。

第一次启动会问你配色和键位。出厂主题是 One Dark Pro，直接确认即可。

功能放在哪里

不用去命令面板里翻，三个常驻位置都能点。

左侧 Olympia 面板

  • 当前环境：编译器版本、编译档位、体检结果、比赛剩余时间
  • 编译与运行：编译并运行、只编译、按评测机编译、提交前体检、对拍、比赛模式
  • 题目与模板：拉取题面、从剪贴板拉题号、打开题面库、插入赛制模板
  • AI 教练与帮助：AI 设置、环境自检、打开官网

底部状态栏

左下角三枚 chip，点一下就执行：洛谷 · C++23（换档位）、编译运行 F9、体检结果。 比赛开始后这里还会出现倒计时。

编辑器标题栏

当前文件右上角放了最常用的四个动作：编译并运行、按评测机编译、提交前体检、拉取题面。

帮助菜单

菜单栏 帮助 里有「文档」「快捷键参考」「欢迎」「报告问题」。 调试器、源代码管理这些竞赛用不到的入口默认从侧栏摘掉了。

编译与评测机档位

本地能过、交上去挂，多数是编译参数不一样。Olympia 直接把评测机的开关拿来用。

三档预设

  • 洛谷：GCC 15.1.0 口径，-std=c++23
  • NOI Linux 2.0（洛谷默认提交）：GCC 9.3.0 口径，-std=c++14
  • 自定义：自己填参数，见 olympia.compiler.customFlags

两档预设共用的开关：-x c++ -fPIC -DONLINE_JUDGE -Wall -fno-asm -lm -march=native。

怎么切

点状态栏的 洛谷 · C++23，或者用命令「选择评测机编译配置」。

三个编译动作和它们的键位：

  • F9 编译并运行
  • Shift+F9 只编译，看有没有错误
  • Ctrl+Shift+F9 按评测机编译（强制 -O2，用来复现评测机行为）

默认 olympia.compiler.optimization 是 none：本地调试保持不优化，报错信息才对得上行号。 想确认 Olympia 到底跑了什么命令，状态栏下方终端会把完整 g++ 命令行打印出来（可用 olympia.compiler.showCompileCommand 关掉）。

系统里已经有编译器、不想用内置的？把 olympia.compiler.path 填成你自己的 g++.exe 路径；留空则优先用内置工具链，其次找 PATH。

提交前体检

只报会在评测机上编译失败的写法，不当代码风格老师。

触发方式：保存时自动扫描（静默，结果进「问题」面板），或按 Ctrl+Alt+Enter 主动体检一次。

检查项为什么会挂对应设置
#pragma GCC optimize、__attribute__((optimize)) 洛谷改过 GCC，这类优化属性在评测机上行为和你本地不一样，常见直接 RE 或答案错 olympia.check.rules.pragmaOptimize
asm、and、or、not、xor 当变量名 MSVC 允许，GNU C++ 里它们是关键字，换个评测机就编译不过 olympia.check.rules.reservedWord
gets、random_shuffle、register C++17 之后标准已经删掉，新评测机直接报错 olympia.check.rules.removedCpp

整体开关是 olympia.check.enabled，保存时扫描是 olympia.check.onSave。体检不会改你的代码，也不会自己弹提示。

跑样例（本地判 AC / WA）

把题面样例当测试用，不联网、不需要账号。

  1. 先用 Ctrl+Alt+P 拉题面，或 Ctrl+Alt+O 打开一份已经缓存的题面。
  2. 写好代码，按 Ctrl+Alt+J。
  3. Olympia 用当前档位编译，把每组样例的输入喂进去，按 token 比对输出，并按题面里写的时限和内存限制判断有没有超时、超内存。

结果给出 AC / WA / RE / TLE / MLE，WA 会把「期望输出」和「你的输出」并排列出来，直接对着看差异。 每组还会打印耗时和峰值内存，超内存时按「峰值 > 上限」判 MLE。

读不到题面或题面里没有样例时，命令会让你先选一份缓存题面，不会凭空判你错。时限认「时限：1000ms」「时限：1 秒」这两种写法， 内存认「内存限制：128.00 MB」「内存：128M」「内存：1GB」这类写法。

峰值内存是每隔 30 毫秒采样一次的，短命进程会漏掉峰值，所以这个数字只会偏小不会偏大： 判了 MLE 就是真超了，没判不代表一定安全。题面没写内存限制时只报峰值、不判 MLE；想强制一条上限就填 olympia.judge.memoryLimitMb。

对拍

正解和暴力互相验证，不用装 Python，也不用手写 fc 脚本。

按 Ctrl+Alt+S，依次选三个文件：正解、暴力（或慢但一定对的写法）、随机数据生成器。 Olympia 把它们都编译好，然后循环：

  • 生成器产一组数据 → 同时喂给两份程序
  • 输出按 token 比对；不一致就停下来
  • 把出问题的输入和两份输出写进工作区的 stress-fail/，命名形如 round-7.*，点开就能查

轮数由 olympia.stress.rounds 控制（默认 100 轮），单个程序的运行上限是 olympia.stress.timeoutMs（默认 2000 ms），超上限按不一致处理。

生成器报错不弹框，那轮直接跳过并继续；想确认的话看 Olympia 输出面板。

抓到不一致时，提示里有 补进题面样例：点一下，这组数据和正解的输出就写进那道题的题面， 变成永久的一组样例，之后每次跑样例都会带上它。题面本来就是普通文本，想再加边界数据，直接在 ## 样例数据 里照着 ### 样例 3 的样子补一段就行。

只有两边都跑完、纯粹输出不一样时才给这个按钮——超时或崩溃的那一轮没有可信的「正确答案」可写。

比赛模式

自己给自己一场有时间的比赛。

按 Ctrl+Alt+C，选时长：60 / 90 / 120 / 180 / 240 / 300 / 360 分钟，也可以自己填。 开始后状态栏出现倒计时，左侧 Olympia 面板的「当前环境」同步显示剩余时间。

  • 关掉窗口、重载界面之后倒计时接着走，不会重置
  • 点一下倒计时可以提前收摊，会先确认一次
  • 再按一次快捷键就是结束比赛模式
  • 倒计时期间 AI 教练不出场：@coach 只会回一句「这一局打完再问」，不会发模型请求。 体检和跑样例照常用——那是自己的程序对样例，不算外援。

题面、模板与离线

拉题面

  • 洛谷：Ctrl+Alt+P 后写 P1001，或粘链接
  • Codeforces：1660C / 1660/C
  • AtCoder：ABC300_A
  • Ctrl+Alt+V 从剪贴板识别题号，不用重打

题面库

按 Ctrl+Alt+O 打开：列表里是缓存过的每道题， 标题、来源、难度、时限、内存、样例组数都直接写在行上，最近拉的排最前面。 按题号搜也按标题搜，打「并查集」就能找到 P3367。 左侧 Olympia 面板的「当前环境」里有一行 题面库：N 份，点它就是打开这个列表； 一份都还没有时这行会变成「还没拉过题面」，点进去直接开始拉。

手写的、或只抓了一半的题面也照样进库：读不出题号就用文件名当题号，不会把整份列表带崩。

题面存成 Markdown 放在 olympia.problem.problemsDir（默认 .olympia/problems）， 之后断网也能用 Ctrl+Alt+O 打开。

Codeforces 的题面网页有 Cloudflare 人机校验，抓不到正文时 Olympia 会留下题目信息和原题链接，并提示你在浏览器里看； 标题、标签、难度走官方接口，需要时把 olympia.problem.cfMetadata 打开（要多等几秒）。

模板与补全

Ctrl+Alt+T 插入起手代码，分 ACM 与 IOI 两套： 快读、freopen、常用头文件这些都在里面。

写 C++ 时补全列表里还有一批竞赛常用写法：快速 IO、freopen、 lower_bound、小根堆、快速幂、并查集、埃氏筛、Dijkstra、BFS 等 20 条。 中英文都能搜到，敲 ios、fast、快速 都会命中同一条。 不想要就把 olympia.templates.cppSnippets 关掉。

拉完题面自动建 main.cpp 的行为是关着的，想要就打开 olympia.problem.templateOnPull。

哪些功能离线可用

  • 离线：编译、运行、体检、跑样例、对拍、比赛模式、模板、已缓存题面
  • 需要联网：拉在线题面、AI 教练

AI 教练（可选）

不绑账号、不订阅，也不经过我们的服务器。

配置

  1. 左侧 Olympia 面板 → AI 教练与帮助 → AI 设置（地址 / 密钥 / 模型）
  2. baseUrl 填 OpenAI 兼容服务的根地址（不含 /chat/completions）
  3. Key 在密码框里输入，存进 Windows 凭据管理器，不写进任何配置文件
  4. 模型列表默认从 {baseUrl}/models 自动拉取（缓存 5 分钟）；拉不到就在 olympia.ai.models 里自己填

不填也能用 Olympia：编译、体检、跑样例、对拍全部不依赖 AI。

使用

聊天面板里输入 @coach，Olympia 会把当前文件的代码一起带上。三个内置指令：

  • /wa：结合题面、样例与你的输出，列出最可能的错因和验证方法
  • /hint：只给方向性提示与关键不变量，不输出完整代码
  • /check：提交前风险清单——边界、整数溢出、复杂度、读入终止、多组数据

命令面板里的 选择 AI 教练使用的模型、设置 AI 教练的 API Key、 显示 AI 教练日志 随时可换可查。

比赛模式进行中教练不出场，详见比赛模式。

装完之后容易卡的地方

双击安装被 SmartScreen 拦住

安装包没有代码签名证书，Windows 会拦一次。点「更多信息 → 仍要执行」即可； 不放心就先用 SHA256SUMS.txt 核对下载到的文件。

提示「安装程序需要下一张磁盘」

分卷没下全，或者文件没放在同一个目录。把 OlympiaSetup.exe 和 OlympiaSetup-1.bin … OlympiaSetup-4.bin 全放进同一个文件夹， 双击 OlympiaSetup.exe；文件名不要改。

F9 报找不到编译器

按 Ctrl+Alt+D 跑一次环境自检，会逐条告诉你它找了哪些路径。 内置工具链在安装目录的 resources\app\toolchain\mingw64\bin\g++.exe （用户版安装器默认在 %LocalAppData%\Programs\Olympia IDE）； 想用系统里的编译器，填 olympia.compiler.path。

本地过了，交上去 WA / RE

先换档位：#include <bits/stdc++.h> 在 NOI 档（GCC 9.3.0 / C++14）下可能报错， 用 Ctrl+Shift+F9 打开 -O2 复现优化后的行为， 再用 Ctrl+Alt+S 对拍找一组反例。

体检报的问题我觉得不影响编译

体检只看会导致编译失败或评测机行为不一致的写法。确实误报时，可以按项关掉 olympia.check.rules.*，或整体关掉 olympia.check.onSave。

左侧栏没有「运行和调试」「源代码管理」，我要怎么用

竞赛用不到，出厂把它们从活动栏摘掉了。需要调试器时打开 olympia.debug.showEntryPoints，入口就回来了； 版本管理可以用命令面板里的 Git 命令。

AI 教练不回话

先跑「环境自检」，它会检查 baseUrl 是否可达、Key 是否已保存； 再执行「显示 AI 教练日志」看请求返回了什么。地址填的是根地址，不要带 /chat/completions。
